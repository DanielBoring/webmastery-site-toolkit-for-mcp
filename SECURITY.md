# Security policy

## Supported versions

Security fixes target the latest stable release of Webmastery Site Toolkit for MCP.
Older releases do not receive separate security backports. Update to the latest
stable release before checking whether a reported issue still occurs.

Reports affecting older versions are welcome; include the affected version and
whether you can reproduce the issue on the latest release.

## Report a vulnerability privately

Use [GitHub's private vulnerability reporting form](https://github.com/DanielBoring/webmastery-site-toolkit-for-mcp/security/advisories/new).
Do not post suspected vulnerabilities, exploit instructions, credentials, or
private site data in a public issue or pull request.

Include the plugin, WordPress, PHP, and MCP Adapter versions; the affected ability;
the minimum role or capability needed; the expected and actual behavior; and
reproduction steps using a disposable test site. Redact passwords, tokens,
Application Passwords, personal information, and production site contents.

The maintainer reviews reports on a best-effort basis. There is no guaranteed
response or resolution deadline. Follow up in the private report so the
investigation stays in one place.

Confirmed issues are assessed for affected versions, impact, and release
requirements. Fixes and public advisories are coordinated through the private
report, including WordPress.org communication when appropriate.

For non-security bugs and feature requests, use the
[public issue templates](https://github.com/DanielBoring/webmastery-site-toolkit-for-mcp/issues/new/choose).
See [the security strategy](docs/security-strategy.md) for maintainer procedures.
